# Release 0.13.0 — Workflow success gates and status aggregation

Adds explicit workflow control-flow for cases where a review/partial result must be persisted but must not trigger later side effects.

## Included

- `WorkflowStep.requires_success_of` declares which ordering dependencies must return `SUCCESS` before a step can run.
- Gated steps are not invoked and appear in `skipped_steps` and `gated_steps`.
- Aggregate workflow status preserves the highest-severity result observed (`FAILURE` > `REVIEW_REQUIRED` > `PARTIAL` > `SUCCESS`), so a later successful storage/cleanup step cannot disguise an earlier review or failure.
- Registry validation requires every success condition to reference a declared dependency. Existing workflow definitions preserve their prior behavior unless they opt into the new field.
