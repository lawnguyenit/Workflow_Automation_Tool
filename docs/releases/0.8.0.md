# Release 0.8.0 — Google Forms API lead intake

## Added

- `source.google_forms_api_response`: pure mapper from one Google Forms API Form + FormResponse pair into the canonical lead event contract.
- `portfolio.lead_management_google_forms_api`: source mapping → lead normalization → manual-review-safe qualification → PostgreSQL event storage.
- Inactive n8n polling export with read-only OAuth placeholders, bounded response pagination, stable `formId:responseId` replay identity, and a separate synthetic manual preview export.
- Contract, OAuth boundary, retry/replay behavior, privacy, and capacity-limit documentation.

## Guarantees and limits

- Exact question-title matching fails closed on schema drift, ambiguous titles, unsupported/multiple answer values, and over-limit fields. Errors do not return response content.
- The Forms API export is inactive, contains no credentials or Form ID, and defaults to local API `DRY_RUN`. No Google consent/API request, n8n UI import, activation, or real response is included in this release's evidence.
- The cursor uses n8n workflow static data and is only a single-instance, low-volume reference. Overlapping executions are not serialized; use an atomic database checkpoint/lease before multi-worker or higher-volume deployment.
- Google consent requires both `forms.body.readonly` and `forms.responses.readonly`; do not grant broad Drive scopes for this path.
- `REAL` model execution remains unsafe to enable without a durable pre-call idempotency and cost gate. This release does not compose CRM or email effects.
