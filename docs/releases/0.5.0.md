# 0.5.0 — GoHighLevel opportunity upsert

## Added

- Added `crm.ghl_upsert_opportunity`, bound as `portfolio.ghl_opportunity_upsert` when `GHL_LOCATION_ID` is configured.
- The adapter handles open opportunities only. It searches by Location, contact, and pipeline; creates if none match, updates exactly one match, and stops for review on ambiguity.
- Added bounded field validation, v3 auth/version headers, PII-suppressed outputs, pagination limits, dry-run/mock/replay behavior, and distinct retryability for read versus uncertain write failures.
- Added a shared PostgreSQL external-effect guard: advisory locks serialize this adapter across API workers, and durable `IN_PROGRESS` / unknown-outcome rows block unsafe retries until reconciliation.
- Documented the module contract, API scopes, reconciliation procedure, official API references, and account/configuration gaps.

## Limits

- Synthetic HTTP tests only; no GHL account, Location, token, pipeline/stage IDs, or live write was available.
- The guard coordinates only adapter instances sharing its PostgreSQL database; other writers to HighLevel remain outside its lock. Unknown/in-progress rows require operator reconciliation and must not be automatically cleared.
- Not composed into the lead workflow until a user-owned GHL account and approved pipeline/stage mapping are configured.
- GHL tags, outbound email, follow-up suppression, source connection, operational alerts/recovery, and n8n UI execution remain incomplete.
