# 0.2.0 — Local lead-management reference instance

## Added

- `lead.intake`: bounded normalization, required-field checks, email shape check, stable source-event requirement, and explicit human-review status when business qualification settings are absent.
- `lead.store`: PostgreSQL persistence with a unique source-event constraint, first-write-wins conflict behavior, same-payload duplicate reporting, and changed-payload review signaling.
- A private local n8n preview export and synthetic integration payload.
- A repeatable PostgreSQL migration for the existing named volume and module documentation describing dedupe, concurrency, review, privacy, and unverified boundaries.

## Verification boundary

- The module/unit checks validate deterministic normalization and failure behavior.
- A local PostgreSQL API run must be recorded separately before claiming database integration evidence.
- The n8n export is static-checked only until import and manual execution are observed in the running n8n instance.
- GHL, OpenAI API, Gmail/Outlook sending, Google Forms/Sheets response ingestion, and public webhook reachability are not connected or live-verified.
- The Google Form is a private unpublished draft with no responses. The user's game VPS was not contacted or changed.

## Safety and known limits

- All reference submissions must be synthetic.
- CRM contact/opportunity identity dedupe, messaging outbox, reply/booking/opt-out/manual-pause suppression, delivery retry, and AI qualification are not implemented in this lead graph.
- The local API returns sanitized workflow output for lead payloads, but the database stores the submitted lead fields. Keep the API loopback/private and do not submit real prospect data.
