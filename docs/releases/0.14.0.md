## Deployment notes and limits

- Upgrade an existing database by applying migrations 008 and 009 before enabling REAL GHL contact or opportunity writes. Fresh database initialization includes both schemas.
- The contact and opportunity payloads require a stable opaque source-event key. Do not place email, phone, or other personal data in it. Keep successful event rows longer than the source retry/replay window; no retention job is included.
- Operators must reconcile an unknown CRM write in HighLevel and update/resolve both applicable PostgreSQL ledgers before retrying. The module does not automate reconciliation.
- These protections cover one source-event key and callers sharing this PostgreSQL database. They do not establish exactly-once delivery across external writers, deduplicate different source events for the same person, or verify a live customer's duplicate policy and pipeline mapping.
- The full lead workflow remains incomplete and unaccepted: Forms OAuth is not granted, there is no GHL client account, no OpenAI API budget/key, and no approved follow-up policy or event-source/sender composition.
