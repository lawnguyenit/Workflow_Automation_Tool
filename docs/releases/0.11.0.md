# Release 0.11.0 — Durable source poll checkpoint

## Added

- `state.source_poll_checkpoint`, a PostgreSQL-backed module for acquire, renew, monotonic commit, and release operations.
- Migration `006-source-poll-checkpoint.sql` stores a hashed source key, timestamp cursor, bounded lease, and most recent completed operation for safe HTTP retries.
- The Forms API n8n template now acquires a per-Form lease, renews after response-page retrieval, releases on an empty poll, and commits only after every response reaches an accepted storage state.
- Fenced tokens prevent expired/replaced runs from moving the cursor. Stable `formId:responseId` storage identity continues to make replayed source events safe for the current PostgreSQL-only composition.
- Unit and synthetic Compose/PostgreSQL integration checks cover overlapping claims, same-run retries, renewal, monotonic commits, idempotent commit/release retries, expiry/reclaim, stale-run rejection, and cleanup.

## Guarantees and limits

- `DRY_RUN`/`REPLAY` do not touch checkpoint storage. `MOCK`/`REAL` require a configured PostgreSQL database and use the API authorization boundary.
- The lease is configured for 900 seconds in the portfolio instance. Expired leases can be reclaimed; an old run cannot commit after expiry, but it may already have completed downstream work. Downstream side-effect modules still need their own durable idempotency/reconciliation.
- Checkpoint cursor semantics are timestamps and belong to the caller. This is not an adapter for opaque page tokens.
- Google OAuth, Forms API schema/question IDs, execution of the imported poller, backlog/load behavior, and live source-to-database behavior remain unverified. The Cloud project setup is pending owner direction; no Google Cloud setting was changed.
