# 0.1.0 — Intelligent Document Intake reference portfolio

## Added

- Platform-neutral contracts, module definitions and implementations, executor bindings, module instances, reusable workflow definitions, concrete workflow-instance bindings, validated workflow graph, and execution runner.
- Fixture/Gmail read module, bounded PDF parser, strict-schema OpenAI extraction module, record validation, PostgreSQL idempotent storage, and Slack notification outbox module.
- FastAPI health/catalog/module/workflow endpoints and importable n8n manual-trigger demo that composes the six module-instance API nodes.
- Docker Compose definition for PostgreSQL, API, and n8n, plus synthetic fixtures and tests.

## Reliability and security behavior

- Source-key uniqueness and `ON CONFLICT` handling give first-write-wins database dedupe under concurrent same-key insertions.
- Notification intents are fingerprinted and conditionally claimed before Slack delivery. Ambiguous send outcomes block automatic resends.
- `MOCK`/`REAL` and live Gmail API calls require `WORKFLOW_API_KEY`; `DRY_RUN`/`REPLAY` remain available without a key for the n8n template. The API does not enforce synthetic-only preview payloads or verify that replay inputs are captured and sanitized, so keep it private and sanitize replay data before submission. This is a shared bearer key, not role-based access control.
- Slack 429/rejection responses are not labeled retryable because the reference module has no delayed requeue path. Operators must reconcile a failed intent before another send attempt.
- API defaults to `DRY_RUN`; errors exclude provider/database response details. Workflow API output excludes raw email attachment bytes and extracted PDF text.
- Documentation records module limits, retries, failure behavior, capacity assumptions, and unverified live integrations.

## Compatibility and limitations

- This is an initial reference implementation, not a production service-level commitment. No live Gmail, OpenAI, Slack, PostgreSQL, or n8n environment was exercised.
- OCR, Gmail pagination/checkpointing, automatic retry scheduling, queues/backpressure, connection pooling, retention jobs, migrations, and production observability are not included.
- Existing data migrations from an earlier release are not applicable; database setup uses the checked-in initial schema.
