# Release 0.12.0 — PII-minimized workflow incident log

Adds a reusable cross-cutting PostgreSQL incident log for `MOCK`/`REAL` module and workflow runs that end `PARTIAL`, `FAILURE`, or `REVIEW_REQUIRED`.

## Included

- Append-once incident recording keyed by workflow/run/attempt digest, with idempotent same-result replay and conflict hold when the result changes.
- Bounded diagnostic allowlist; request/business payloads, error text, secrets, and raw run/correlation IDs are not stored.
- Authenticated list, detail, and operator-resolution API routes. Resolution is acknowledgement only and never triggers a retry.
- PostgreSQL migration 007 and fresh-install schema, module contract documentation, and a synthetic database/API integration harness.

## Reliability and data handling

- Incident persistence is best effort. If the database is unavailable, the workflow response is preserved but incident durability is lost for that run.
- There is no external alert delivery, retry worker, dead-letter processing, pagination beyond a 100-item limit, retention job, or production observability. These gaps remain explicit.
- The shared API bearer key is not role-based access control. Keep the service private.
